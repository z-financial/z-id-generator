## Main Design Choices

- `AbstractGeneratorRuntimeManager` now accepts a `RuntimeIdGeneratorFactory`.
  This keeps local/config mode on the default generator path while allowing
  MySQL mode to create `LeasedIdGenerator` instances.
- Added `RuntimeCreateContext` as an opaque creation context.
  MySQL mode stores the acquired `LeaseHandle` in it before generator creation.
- `RuntimeGeneratorEntry` is now protected and carries:
  - generator id
  - generator name
  - worker id
  - manager-local instance id
  - `GeneratorInstanceProperties`
  - generator instance
  - runtime attachment
- Added hooks:
  - `beforeCreate(...)`
  - `attachRuntime(...)`
  - `onCreateFailure(...)`
  - `onStopGenerator(...)`
- `MysqlGeneratorRuntimeManager` acquires a worker lease before creating a
  generator, releases it on create failure / stop / shutdown, and renews it in
  background tasks.

## Concurrency And Lifecycle Behavior

- Runtime map/index changes still use the existing single read/write lock.
- Stop hooks run after the entry is removed from the runtime maps, outside the
  runtime lock, so MySQL lease release does not block map reads.
- Background cleanup uses stale-safe `stopGeneratorInstance(RuntimeGeneratorEntry)`.
  It only removes the entry if generator id, worker id, and instance id still
  match the current runtime map value.
- MySQL renewal uses one in-flight renewal task per runtime entry to avoid
  overlapping DB renews for the same worker.
- If DB renew returns `false`, the runtime entry is stopped immediately because
  the lease handle is stale or ownership is lost.
- If DB renew throws, the local deadline is not extended. The generator keeps
  running only until its local safe deadline expires.
- If the renew worker queue is saturated, new renew tasks are discarded and
  future renew scheduling is disabled. Existing local deadlines then expire
  naturally and the cleaner removes entries.

## Validation Added

- Added `WorkerCandidateUnavailable` error code and
  `IdGenerationException.workerCandidateUnavailable(...)`.
- `startGeneratorInstance(generatorId)` skips unavailable candidates and keeps
  trying remaining workers.
- `MysqlGeneratorRuntimeConfig` validates lease term, local safe term, renewal
  interval, cleaner interval, pool sizes, and queue size.
- MySQL owner token generation validates that `serverInstanceId:uuid` fits the
  existing `owner_token VARCHAR(64)` schema.

## Remaining Risks / TODOs

- The MySQL runtime manager has no real MySQL integration test yet. Current test
  coverage uses fake `RegistrationLoader` and `LeaseManager`.
- Renew saturation currently chooses fail-fast availability loss: it stops
  scheduling future renews and lets local deadlines expire. This is safe for
  duplicate prevention, but operationally strict.
- Owner token uses `serverInstanceId:uuid`; long server ids are rejected because
  the DB column is `VARCHAR(64)`.
